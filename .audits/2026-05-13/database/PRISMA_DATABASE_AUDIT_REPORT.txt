1. N+1 QUERY PATTERN - Client Storage Usage Calculation
   Location: /src/app/api/admin/clients/route.ts:64-86
   Severity: HIGH
   Impact: Performance degradation with scale (O(n) queries for n clients)
   
   Current Code:
   ```typescript
   const clientsWithUsage = await Promise.all(
     clients.map(async (client) => {
       const usage = await prisma.photo.aggregate({
         where: {
           gallery: {
             event: {
               clientId: client.id,
             },
           },
         },
         _sum: { fileSize: true },
         _count: true,
       });
       return { ...client, usedStorageBytes: usage._sum.fileSize };
     })
   );
   ```
   
   Problem: For 100 clients, this executes 101 queries (1 for clients + 100 for usage)
   
   Recommendation:
   - Use Client.usedStorage field (already exists in schema line 34)
   - Remove aggregate query entirely
   - The field is atomically maintained via conditional updates in upload/delete flows
   
   Optimized Code:
   ```typescript
   const clients = await prisma.client.findMany({
     select: {
       id: true,
       nama: true,
       email: true,
       phone: true,
       instagram: true,
       storageQuotaGB: true,
       usedStorage: true, // Already tracked atomically
       isApproved: true,
       createdAt: true,
       updatedAt: true,
     },
     orderBy: { createdAt: 'desc' },
     take: limit,
     skip,
   });
   
   const clientsWithUsage = clients.map(client => ({
     ...client,
     usedStorageBytes: client.usedStorage.toString(),
     photoCount: 0, // Remove if not critical, or add _count relation
   }));
   ```
   
   Expected Impact: 100x reduction in queries (101 → 1)

11. RACE CONDITION - Selection Submission Check
    Location: /src/app/api/public/gallery/[token]/submit/route.ts:65-67
    Severity: MEDIUM
    Impact: Potential duplicate selection if concurrent submissions
    
    Current Code:
    ```typescript
    if (gallery.selections.length > 0) {
      return errorResponse("Selection already submitted", 400);
    }
    
    const selection = await prisma.selection.create({...});
    ```
    
    Problem: Check-then-act race condition
    
    Recommendation: Use transaction with SELECT FOR UPDATE or unique constraint
    
    Optimized Code:
    ```typescript
    try {
      await prisma.$transaction(async (tx) => {
        const gallery = await tx.gallery.findUnique({
          where: { clientToken: token },
          include: { selections: true },
        });
        
        if (gallery.selections.length > 0) {
          throw new Error('ALREADY_SUBMITTED');
        }
        
        await tx.selection.create({
          data: {
            galleryId: gallery.id,
            photos: {
              create: photoIds.map(photoId => ({ photoId })),
            },
          },
        });
        
        await tx.gallery.update({
          where: { id: gallery.id },
          data: { isSelectionLocked: true },
        });
      });
    } catch (err) {
      if (err.message === 'ALREADY_SUBMITTED') {
        return errorResponse("Selection already submitted", 400);
      }
      throw err;
    }
    ```
