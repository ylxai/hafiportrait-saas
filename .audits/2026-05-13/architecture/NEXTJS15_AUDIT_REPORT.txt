2. SERVER VS CLIENT COMPONENT BOUNDARIES
================================================================================

STATUS: ⚠️ NEEDS ATTENTION

HIGH ISSUES:

[HIGH-1] Excessive Client Components in admin dashboard
Locations:
  - src/app/(dashboard)/admin/clients/page.tsx (line 1: 'use client')
  - src/app/(dashboard)/admin/events/page.tsx (line 1: 'use client')
  - src/app/(dashboard)/admin/galleries/page.tsx (line 1: 'use client')
  - src/app/(dashboard)/admin/events/[id]/page.tsx (line 1: 'use client')
  - src/app/(dashboard)/admin/galleries/[id]/page.tsx (line 1: 'use client')
  - src/app/(dashboard)/admin/page.tsx (line 1: 'use client')

Issue: All admin pages are Client Components using SWR for data fetching.
This prevents:
  - Server-side data fetching and streaming
  - Automatic request deduplication
  - SEO optimization
  - Initial page load performance

Impact: HIGH - Missed opportunities for performance optimization and SSR benefits.

Recommendation:
1. Convert page shells to Server Components
2. Move data fetching to Server Components using async/await
3. Extract interactive UI into separate Client Components
4. Use React Server Components composition pattern

Example refactor for src/app/(dashboard)/admin/page.tsx:

BEFORE (Current):
  'use client';
  export default function DashboardPage() {
    const { data, isLoading } = useSWR('/api/admin/stats', fetcher);
    // ... render logic
  }

AFTER (Recommended):
  // Server Component (no 'use client')
  async function DashboardPage() {
    const stats = await fetch('/api/admin/stats').then(r => r.json());
    return <DashboardClient initialData={stats} />;
  }

  // Separate Client Component for interactivity
  'use client';
  function DashboardClient({ initialData }) {
    const { data } = useSWR('/api/admin/stats', fetcher, { fallbackData: initialData });
    // ... interactive UI
  }
